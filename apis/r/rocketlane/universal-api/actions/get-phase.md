# Rocketlane: Get Phase

Retrieves a phase from Rocketlane.

```
GET https://connect.mindcloud.co/v1/universal/rocketlane/latest/actions/get-phase
```

Authenticate with `Authorization: Bearer $MINDCLOUD_API_KEY` and pass a Rocketlane `connectionId` ([setup](../authentication.md)).

## Example request

```bash
curl -X GET "https://connect.mindcloud.co/v1/universal/rocketlane/latest/actions/get-phase?connectionId=$CONNECTION_ID&phaseId=1" \
  -H "Authorization: Bearer $MINDCLOUD_API_KEY"
```

```js
const params = new URLSearchParams({
  connectionId,
  "phaseId": "1"
});

const response = await fetch(`https://connect.mindcloud.co/v1/universal/rocketlane/latest/actions/get-phase?${params}`, {
  headers: {
    Authorization: `Bearer ${process.env.MINDCLOUD_API_KEY}`
  }
});

const { success, data } = await response.json();
```

## Inputs

Arguments are sent as query string parameters ([conventions](../arguments.md)).

| Key | Type | Required | Description |
| --- | --- | --- | --- |
| `phaseId` | number | yes | The `identifier` of the phase is generated by the system and can be used to identify the phase globally. |
| `includeFields` | list<string> | no | This query parameter allows you to specify which fields should be returned in the response body by selecting from the drop down. To get the relevant fields, use comma separated values. If the field is left blank, the default properties are returned. |
| `includeAllFields` | boolean | no | This query parameter allows you to specify if all the fields should be returned in the response body. If the field is left blank, the default properties are returned. |

## Response

```json
{
  "success": true,
  "data": [
    {
      "createdAt": 1,
      "createdBy": {},
      "dueDate": "string",
      "dueDateActual": "string",
      "phaseId": 1,
      "phaseName": "Ava Chen",
      "private": true,
      "project": {},
      "startDate": "string",
      "startDateActual": "string",
      "status": {},
      "updatedAt": 1,
      "updatedBy": {}
    }
  ],
  "meta": {}
}
```

### Response fields

| Key | Type | Description |
| --- | --- | --- |
| `createdAt` | number | The time when the phase was created. The referenced time will be in epoch millis. |
| `createdBy` | object | The team member who created the phase. |
| `dueDate` | string | The day on which the phase's execution is planned to be completed. The due date is mandatory. The dueDate must be on or after the given startDate. The format for the due date is _YYYY-MM-DD_. |
| `dueDateActual` | string | The date when phase status gets changed to completed. The status can be either the default provided status (completed) or a custom status that is labelled under the Completed category.  It will be null if the phase is yet to be completed. The format for the actual due date is _YYYY-MM-DD_. |
| `phaseId` | number | The phases's unique, system-generated identifier, which can be used to identify the phase globally. |
| `phaseName` | string | The name of the phase. |
| `private` | boolean | Describes the privacy of the phase i.e. if it is private or shared. |
| `project` | object | The `project` associated with phase. |
| `startDate` | string | On this date the phase's execution officially begins. . The due date is mandatory. The format for the start date is _YYYY-MM-DD_. |
| `startDateActual` | string | The date on which the phase status is changed to in progress. The status can be either the default said status (in progress) or custom statuses that are categorised as in progress. It can be null for phases that have not yet begun. The format for the actual start date is _YYYY-MM-DD_. |
| `status` | object | The phase status value along with the label will be present here. |
| `updatedAt` | number | The time when the phase was last updated. Any changes that's related to the phase are captured and specified here in epoch millis. |
| `updatedBy` | object | The team member who updated the phase |

## Native endpoint

Through the native Rocketlane API, this operation is `GET /1.0/phases/:phaseId` (base URL `https://api.rocketlane.com/api`). The Universal API call above is translated to it by MindCloud, including authentication. See the [native action reference](../../native-api/actions/get-phase.md) for the provider-specific parameters and requirements.
