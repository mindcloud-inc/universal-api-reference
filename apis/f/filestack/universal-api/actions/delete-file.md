# Filestack: Delete File

Deletes an existing file from Filestack.

```
DELETE https://connect.mindcloud.co/v1/universal/filestack/latest/actions/delete-file
```

Authenticate with `Authorization: Bearer $MINDCLOUD_API_KEY` and pass a Filestack `connectionId` ([setup](../authentication.md)).

## Example request

```bash
curl -X DELETE "https://connect.mindcloud.co/v1/universal/filestack/latest/actions/delete-file?connectionId=$CONNECTION_ID&handle=itnd50g6QzehEsWjDGij&policy=string&signature=string" \
  -H "Authorization: Bearer $MINDCLOUD_API_KEY"
```

```js
const params = new URLSearchParams({
  connectionId,
  "handle": "itnd50g6QzehEsWjDGij",
  "policy": "string",
  "signature": "string"
});

const response = await fetch(`https://connect.mindcloud.co/v1/universal/filestack/latest/actions/delete-file?${params}`, {
  headers: {
    Authorization: `Bearer ${process.env.MINDCLOUD_API_KEY}`
  }
});

const { success, data } = await response.json();
```

## Inputs

Arguments are sent as query string parameters ([conventions](../arguments.md)).

| Key | Type | Required | Description |
| --- | --- | --- | --- |
| `handle` | string | yes | The Filestack file handle to delete. Example: `itnd50g6QzehEsWjDGij`. |

### Advanced

| Key | Type | Required | Description |
| --- | --- | --- | --- |
| `policy` | string | yes | Security policy generated by your backend for the delete request. |
| `signature` | string | yes | Signature generated by your backend for the delete request. |

## Response

The response envelope is `{ "success": true, "data": [...], "meta": {} }`. The `data` schema for this action is dynamic; it mirrors what the native Filestack API returns.

## Native endpoint

Through the native Filestack API, this operation is `DELETE /file/:handle` (base URL `https://www.filestackapi.com/api`). The Universal API call above is translated to it by MindCloud, including authentication. See the [native action reference](../../native-api/actions/delete-file.md) for the provider-specific parameters and requirements.
